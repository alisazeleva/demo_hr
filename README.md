# demo_hr: Acme HR

A dummy HR database (SQL Server) and a Power BI report on top of it, for the fictional company **Acme Corporation**.

**All data is synthetic.** The company, its employees (151 on 2026-11-16, 171 by 2030), their names, salaries, ratings, leave records and pictures are generated for demonstration only, and any resemblance to real people is a coincidence. The patterns in the data (gender, pay, ratings) are random and illustrate how the report works; they are not findings about real workforces.

## What it contains

- **Data:** 151 current employees on 2026-11-16 (1 CEO and 150 in 5 departments), their job and pay history, annual reviews and leave, all generated by the scripts in `sql/` with a fixed seed, so every run gives identical data. The first load describes the company on 2026-11-16; `sql/extend_data.sql` then adds records up to 2030-12-31 (up to 5 hires a year, 171 employees at the end) without changing existing ones. The report shows the company as of its refresh date (limited to 2026-11-16 to 2030-12-31); currency is EUR.
- **Report:** `Acme HR Demo.pbip`, a Power BI project (PBIR report and TMDL model) with a Home page and seven pages: Workforce, Organization, Career, Compensation, Performance, Leave and a hidden Employee profile page opened by drill-through.

## Build the database

SQL Server Express with a named instance `.\SQLEXPRESS` and Windows authentication are assumed. Run the scripts in order from the repository root:

```
sqlcmd -S ".\SQLEXPRESS" -E -C -b -i sql/00_create_database.sql
sqlcmd -S ".\SQLEXPRESS" -E -C -b -d DemoHR -f 65001 -i sql/01_create_tables.sql
...
sqlcmd -S ".\SQLEXPRESS" -E -C -b -d DemoHR -f 65001 -W -i sql/99_full_validation.sql
```

Run every file from `01` to `14` the same way, in numeric order (`12` sets the profile picture file names; run `14` with `-I`). Then extend the data to 2030-12-31 (it makes a verified backup first) and validate:

```
sqlcmd -S ".\SQLEXPRESS" -E -C -b -I -d DemoHR -f 65001 -i sql/extend_data.sql
sqlcmd -S ".\SQLEXPRESS" -E -C -b -I -d DemoHR -f 65001 -W -i sql/99_full_validation.sql
```

No passwords or secrets are stored anywhere.

## Open the report

Open `Acme HR Demo.pbip` in Power BI Desktop and press Refresh. The two parameters `SqlServer` (default `.\SQLEXPRESS`) and `SqlDatabase` (default `DemoHR`) point to your database. The report's reference date is the refresh date; to see it as of another date, set the parameter `ReferenceDateOverride` and refresh (clear it again afterwards). See `DESIGN.md` for the design rules and the layout of each page.

## Checks

```
pip install -r tests/requirements.txt
python -m pytest tests -q
```

The tests check the report and model files without Desktop: JSON schemas, measure descriptions and comments, fields and bookmarks that exist, the info pop-up on every page, that no filter or slicer selection (for example an employee name) is saved in the report files, and that no personal paths, e-mail addresses or secrets are in tracked files. `tests/measures.dax` holds expected values for the measures; run it against the open model in Power BI Desktop's DAX query view and expect no `FAIL` row.

## Validation note

`sql/99_full_validation.sql` runs 49 checks and all of them pass once script 12 has run. The database stores only the picture file names (`EMP-######.jpg`); the pictures themselves are outside it.

## Profile pictures

Work in progress: sheets 1 to 9 (EMP-000001 to EMP-000144) are done; sheet 10 (EMP-000145 to EMP-000151) and the 20 people hired after 2026-11-16 (EMP-000152 to EMP-000171, no prompts yet) are still to be made. How the pictures are made, cut and loaded into Power BI, step by step: [`images/README.md`](images/README.md). In short: `images/prompts/` has ten prompts for 4 x 4 contact sheets of fictional faces (made by hand in an image tool), `images/sheet_map.csv` maps each cell to an employee number, `python images/crop_sheets.py` cuts the saved sheets into 240 x 240 JPEGs named `EMP-######.jpg`, and Power BI reads them from the folder in the `ProfilePicturesFolder` parameter (`C:\DemoHR\profiles`, outside the repo) into the `ProfilePictures` table. An employee without a file simply has no picture. The sheets and the cut pictures are not in the repository (they are git-ignored); you make them yourself with the prompts.
