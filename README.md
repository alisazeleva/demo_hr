# demo_hr: Acme HR

A dummy HR database (SQL Server) and a Power BI report on top of it, for the fictional company **Acme Corporation**.

**All data is synthetic.** The company, its employees (151 on 2026-11-16, 171 by 2030), their names, salaries, ratings, leave records are generated for demonstration only, the profile pictures are AI-generated, and any resemblance to real people is a coincidence. The patterns in the data (gender, pay, ratings) are random and illustrate how the report works; they are not findings about real workforces.

## What it contains

- **Data:** 151 current employees on 2026-11-16 (1 CEO and 150 in 5 departments), their job and pay history, annual reviews and leave, all generated by the scripts in `sql/` with a fixed seed, so every run gives identical data. The first load describes the company on 2026-11-16; script 15 then adds records up to 2030-12-31 (up to 5 hires a year, 171 employees at the end) without changing the earlier ones. The report shows the company as of its refresh date (limited to 2026-11-16 to 2030-12-31); currency is EUR.
- **Report:** `Acme HR Demo.pbip`, a Power BI project (PBIR report and TMDL model) with a Home page and seven pages: Workforce, Organization, Career, Compensation, Performance, Leave and a hidden Employee profile page opened by drill-through.

## Build the database

SQL Server Express with a named instance `.\SQLEXPRESS` and Windows authentication are assumed. One command, run from the repository root, builds the whole database with data up to 2030-12-31 (it takes under a minute):

```
sqlcmd -S ".\SQLEXPRESS" -E -C -b -I -f 65001 -i sql/build_all.sql
```

`sql/build_all.sql` creates the database `DemoHR`, runs the scripts below in order and ends with the validation summary (all 49 checks must pass). It stops without changing anything if `DemoHR` already exists; to rebuild, drop the database first. Every build gives the same data.

To run the steps one by one instead, run the scripts in order from the repository root:

```
sqlcmd -S ".\SQLEXPRESS" -E -C -b -i sql/00_create_database.sql
sqlcmd -S ".\SQLEXPRESS" -E -C -b -d DemoHR -f 65001 -i sql/01_create_tables.sql
...
sqlcmd -S ".\SQLEXPRESS" -E -C -b -d DemoHR -f 65001 -W -i sql/99_full_validation.sql
```

Run every file from `01` to `15` the same way, in numeric order (`12` sets the profile picture file names; run `14` and `15` with `-I`). Scripts `01` to `12` build the company as it is on 2026-11-16 with its history; `15` adds the data from 2026-11-17 to 2030-12-31 (its parts are in `sql/15_generate_2027_2030/` and run only through it).

No passwords or secrets are stored anywhere.

## Open the report

Open `Acme HR Demo.pbip` in Power BI Desktop and press Refresh. The two parameters `SqlServer` (default `.\SQLEXPRESS`) and `SqlDatabase` (default `DemoHR`) point to your database. The report's reference date is the refresh date; to see it as of another date, set the parameter `ReferenceDateOverride` and refresh (clear it again afterwards). See `DESIGN.md` for the design rules and the layout of each page.

## Checks

```
pip install -r tests/requirements.txt
python -m pytest tests -q
```

The tests check the report and model files without Desktop: JSON schemas, measure descriptions and comments, fields and bookmarks that exist, the info pop-up on every page, that no filter or slicer selection (for example an employee name) is saved in the report files, and that no personal paths, e-mail addresses or secrets are in tracked files. `tests/measures.dax` holds expected values for the measures; run it against the open model in Power BI Desktop's DAX query view and expect no `FAIL` row.

## Validation note

`sql/99_full_validation.sql` runs 49 checks and all of them pass once script 12 has run. The database stores only the picture file names (`EMP-######.jpg`); the pictures themselves are outside it.

## Profile pictures

Work in progress: sheets 1 to 9 (EMP-000001 to EMP-000144) are done; sheets 10 and 11 (EMP-000145 to EMP-000171, including the 20 people hired after 2026-11-16) are still to be made. How the pictures are made, cut and loaded into Power BI, step by step: [`images/README.md`](images/README.md). In short: `images/prompts/` has eleven prompts for 4 x 4 contact sheets of fictional faces (made by hand in an image tool), `images/sheet_map.csv` maps each cell to an employee number, `python images/crop_sheets.py` cuts the saved sheets into 240 x 240 JPEGs named `EMP-######.jpg`, and Power BI reads them from the folder in the `ProfilePicturesFolder` parameter (`C:\DemoHR\profiles`, outside the repo) into the `ProfilePictures` table. An employee without a file simply has no picture. The sheets and the cut pictures are not in the repository (they are git-ignored); you make them yourself with the prompts.
